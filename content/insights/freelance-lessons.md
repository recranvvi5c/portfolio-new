Most project problems start before a single line of code is written. Good scoping prevents them.

## Write down what's *not* included

A clear "out of scope" list is just as valuable as the feature list. It sets expectations early.

## Break work into milestones

Smaller milestones with demos make progress visible and let both sides adjust course early.

## Add a buffer — and say so

Unknowns are normal. I add a buffer to every estimate and explain why, which builds trust instead of eroding it.

## Put change requests in writing

New ideas are welcome. They just get their own estimate, so nobody is surprised by the final bill.
